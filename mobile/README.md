# Stylora mobile

Flutter client source for Android and iOS. The mobile client uses Supabase Auth
for sign-in and a local SQLite database for editable drafts. It does **not**
replace the existing Django REST API or modify the existing web client.

## Current capability boundary

This first mobile implementation is intentionally offline-first:

- Photo and video imports are copied into app-private storage; the picked
  originals are never edited in place.
- Draft names and JSON edit-operation stacks are saved to SQLite.
- Photo preview, before/after comparison, undo/redo, and JPG/PNG export run on
  device. JPG quality is configurable.
- Video preview and basic playback controls are available. Video edits are
  stored as draft operations, but this build does not render MP4 files.
- Rich project sync is not enabled: the current Django `Project` model has no
  media-kind, operation-stack, or cloud-asset fields. No original media is
  silently uploaded.
- AI enhancement, audio-track mixing, animated titles, arbitrary crop handles,
  full filter parity in the live preview, and server-side account deletion
  require additional native/backend work. The UI labels these unavailable
  features rather than pretending they completed.

The old FFmpegKit packages have been retired upstream. Do not add an abandoned
FFmpegKit artifact to production; select and validate a maintained native
encoder (including iOS licensing and Android ABI coverage) before enabling
video export.

## Requirements

- Current stable Flutter SDK and Dart SDK compatible with the SDK constraint in
  `pubspec.yaml`
- Android Studio/Xcode for the target platform
- A Supabase project with email/password authentication enabled
- Existing Django API deployment only for future project synchronization; this
  client currently uses Supabase Auth directly and keeps project files local

## Generate native platform projects

Platform boilerplate is generated by Flutter for the installed SDK version; it
is not hand-copied from an older Flutter release.

From the repository root in PowerShell:

```powershell
flutter create --platforms=android,ios --org com.stylemirror --project-name style_mirror mobile_platform_shell
Copy-Item mobile_platform_shell\android mobile\android -Recurse
Copy-Item mobile_platform_shell\ios mobile\ios -Recurse
Remove-Item mobile_platform_shell -Recurse -Force
Set-Location mobile
flutter pub get
```

Configure platform media descriptions and permission declarations in the
generated Android manifest and iOS `Info.plist`. Request only the photo/video
library access needed by the picker. On Android 13+ declare the relevant
granular `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` permissions; configure
Android 14 selected-media access where required by the target SDK. Set the iOS
`NSPhotoLibraryUsageDescription` and `NSPhotoLibraryAddUsageDescription`
messages. Test iOS limited-library selection and Android system photo-picker
behavior on real devices.

## Supabase setup

Set the project URL and **public anon key** at run time. Never put the Supabase
service-role key in a mobile binary:

```powershell
flutter run `
  --dart-define=SUPABASE_URL=https://YOUR_PROJECT.supabase.co `
  --dart-define=SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
```

Enable email/password auth and email confirmation in Supabase Auth. Configure
the verification and reset-email templates, deep-link redirect allowlists,
rate limits, and SMTP delivery for the project. The access/refresh session is
stored via `flutter_secure_storage` (Android Keystore / iOS Keychain).

## Development and verification

```powershell
dart format lib test
flutter analyze
flutter test
flutter run --dart-define=SUPABASE_URL=... --dart-define=SUPABASE_ANON_KEY=...
```

Run photo import, denied/limited permission, gallery-save and video playback
checks on physical devices. Emulator/simulator permissions and gallery APIs can
differ from production devices.

## Data and privacy notes

- Draft database: app-private SQLite file, `style_mirror.db`.
- App-private SQLite/media files are not application-level encrypted at rest;
  use OS device encryption and add an encrypted database/file layer if the
  product threat model requires protection on unlocked or compromised devices.
- Imported sources: app-private `originals/` directory.
- Exported intermediates: app-private `exports/`; successful photo exports are
  also written to the user's gallery on request.
- Clear-cache only removes the app's temporary directory. It does not delete
  projects or imported source files.
- Sign-out uses Supabase Auth. A server-authorized account-deletion endpoint
  does not exist in the current backend and must be added before offering
  in-app deletion.
